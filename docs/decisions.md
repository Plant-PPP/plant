## 2026-10-07 · Profiles, consents and audit log (PLA-16)

- **`REVOKE ALL` before every grant.** With `auto_expose_new_tables = false`, a new table in `public` still gives TRUNCATE, REFERENCES, TRIGGER and MAINTAIN to `anon`, `authenticated` and `service_role` by default. Every table runs `REVOKE ALL` from the API roles and removes those four from `service_role`, which with auto-expose off gets nothing else: it ends up with no privileges, and the first server code that uses it brings its own `GRANT`. `schema_rls_and_grants_test.sql` fails if `anon` has any privilege on a table in `public` or `private`, or if anyone other than the owner has one of those four.
- **Extensions:** `CREATE EXTENSION … WITH SCHEMA extensions`, always. In `public` every function of the extension would be exposed as an RPC; the floor checks it.
- **Shape of owned tables**: `user_id uuid NOT NULL DEFAULT auth.uid() REFERENCES auth.users (id) ON DELETE CASCADE` (the default is what allows inserting without a grant on `user_id`), primary key `uuid DEFAULT gen_random_uuid()` (a sequence id reveals how much others write), every `*_id` reference to another owned table as a composite FK with `user_id` (to a partitioned table, also with its partition key; if it is optional, `ON DELETE SET NULL (<column>)` so `user_id` is not nulled) and unique keys that include `user_id` or only columns the server generates (such as `id`). A one-row-per-user table (such as `profiles`) uses `user_id` as its primary key and has no `id`. A uuid that references nothing does not end in `_id` (for example `idempotency_key`), and a list of references goes in a join table, not in a `uuid[]`. `authenticated` writes only through column-level grants, never on `id`, `user_id` or columns the server maintains. A Storage path the user writes carries `CHECK (starts_with(<column>, user_id::text || '/'))`; the floor adds that check with the first table that has one. A partitioned table has primary key `(user_id, <partition key>, id)`, and every partition gets `ENABLE ROW LEVEL SECURITY` and the same `REVOKE ALL` with no grants: it is read and written through the parent. Our own helper functions (not `auth.uid()`) do not go in a `CHECK`, a default, a policy, an expression index or a generated column: they run as the user and would need EXECUTE. Use the expression or a `DOMAIN`, or a column the server maintains with a trigger (for example, the name without accents for search) and a plain index on it. The pgTAP floor checks `user_id` NOT NULL and cascading from `auth.users`, ids without sequences, unique keys with `user_id` or server-generated, that every uuid `*_id` column is its single-column primary key or an FK (paired with `user_id` when it points to another owned table), that there are no `uuid[]` columns, and write grants only per column and never on `user_id`; each table's two-user test covers the rest.
- **Global reference tables** (quotes, instruments) arrive with their feature and add a narrow exception to the floor: no `user_id`, only SELECT for `authenticated` and a `FOR SELECT USING (true)` policy.
- **Closed values as Postgres enums** (`reference_dollar`, `consent_kind`), so the generated types bring the unions and the TypeScript does not copy the literals.
- **Account holders are not in `profiles` yet.** They arrive with the feature that uses them (accounts and holdings), like every other table.
- **`consents` is a history.** Withdrawing a consent is a new row with `granted = false`; the current state is the latest row per kind. `granted` has no default, so every row says explicitly whether it grants or withdraws.
- **`audit_log` lives in `private` and has no FK to `auth.users`**, so the trail survives account deletion. It has no policies or grants: the PLA-21 writer brings its own and, on the still-empty table, decides `outcome`, the action vocabulary (a table with an FK), the shape and cap of `metadata` and retention. `metadata` never carries emails, IPs, amounts or document text.
- **plpgsql_check runs inside pgTAP**, because `supabase db lint` skips trigger functions, which today are all of them.
- **The CI `database` job uses the CLI pinned in `package.json`** (`pnpm exec supabase`) and does not log in to ghcr.io, so the workflow stays at `contents: read`. If the image registry starts rate-limiting pulls, the login gets added.

## 2026-10-07 · Monorepo (PLA-7)

- **Packages export TypeScript, no build.** `@plant/shared`, `sources`, `core` and `jobs` point `exports` at `src/index.ts` and `apps/web` compiles them with `transpilePackages`. That way there is no `dist` that goes stale and no build step before `pnpm dev:up`. If a package ever runs outside Next (for example a Temporal worker), that package adds its build.
- **The Supabase CLI is pinned in `package.json`** (`supabase` as an exact devDependency) and used with `pnpm exec supabase`. One version source for local, hooks and CI.
- **Local Inngest with `inngest-cli` pinned in `package.json`.** `pnpm dev:up` runs the dev server with `--no-discovery` pointing at `/api/inngest`. The `ping` function (event `plant/ping`) stays as a check that the endpoint is registered in every environment.
- **Local variables in two files.** `apps/web/.env.local` comes from `vercel env pull` (AI keys) and `apps/web/.env.development.local` is written by `pnpm env:local` with local Supabase. Next loads the second on top of the first, so they never overwrite each other.
- **Tests with Jest + ts-jest**, same as the reference app.
- **Forbidden-words check without writing the word.** `scripts/check-forbidden-words.sh` reads the list from `FORBIDDEN_WORDS` (an environment variable locally and a secret in CI), so the word never appears in the repo. Where it runs, below.
- **`ci.yml` starts with the `ci` job.** The `database` job (append-only migrations, up-to-date types, pgTAP and `plpgsql_check`) comes with the base schema (PLA-16), when there are migrations to check. The turbo remote cache comes later: for now the local Actions cache is enough.
- **Inngest mode comes from `NODE_ENV`, not `INNGEST_DEV`.** The client sets `isDev` only under `next dev`. In dev mode Inngest does not verify request signatures, so a stray variable in Vercel cannot open `/api/inngest` in production.
- **Turbo with a `transit` node.** `typecheck`, `lint` and `test` depend on `transit`, which only propagates `^transit`: the cache is invalidated when the source of a package you depend on changes, without tasks waiting on each other. `check` = `typecheck` + `lint`.
- **Shared devDependencies go in the `catalog`** of `pnpm-workspace.yaml` (TypeScript, Jest, ESLint, types), so packages don't drift to different versions. Packages share `eslint.packages.mjs`.
- **Package boundaries in a script** (`scripts/check-package-boundaries.mjs`, runs in CI) over the dependencies each workspace `package.json` declares: `shared` depends on nothing, `sources` and `core` only on `shared`, `jobs` on all three, and only `jobs` and `web` declare `inngest`.
- **`auto_expose_new_tables = false`** in `supabase/config.toml`, same as in the hosted projects: every table needs its `GRANT`.
- **`pnpm audit` also covers devDependencies**, because they run in CI and on everyone's machine. Fixes that have not arrived through the parent package yet go in `overrides`, and an advisory with no fixed version goes in `auditConfig.ignoreGhsas` with the reason.
- **Dependabot waits 7 days** before proposing a new version (`cooldown`). The same limit in pnpm (`minimumReleaseAge`) waits until the current dependencies are more than a week old; today it would force downgrading Next and turbo.
- **The forbidden-words check fails closed in CI**: without the secret it fails on push and on same-repo PRs (it only skips forks and Dependabot), and it also checks every commit of the PR (diff, file names, message and author) and the branch name. It runs before any other script from the branch, and `forbidden-words.yml` repeats it on every push to any other branch, with or without a PR. Logs never show the matching text: only how many matches there are, commit ids and paths. It protects against leaking the word by accident, not against someone with push access, who can read the secret by editing the workflow. Locally the `commit-msg` hook and pre-push repeat it, over every branch you push.
- **`/api/inngest` does not accept unsigned syncs** (`enableUnauthedSync: false`). Threat model in `docs/threat-models/2026-10-07-endpoint-inngest.md`.
- **Base security headers** in `next.config.ts` (no iframes, `nosniff`, `Referrer-Policy`). The nonce-based CSP arrives with login (PLA-17).
- **The `.claude/settings.json` deny list is an aid, not the boundary.** What really protects `staging` and `production` is the GitHub ruleset (required PR, green CI, no force push or deletion).
- **No telemetry yet.** OpenTelemetry with Dash0 and PostHog events come with PLA-21; until then `/api/inngest` and the home page emit nothing.
- **Ported skills:** the ones the plan lists (§2 ter), with `enforce-tenant-isolation` turned into `enforce-owner-isolation`. The night-autonomy ones have no skill of their own: the mode is set only by an explicit request and is described in `_shared/night-shift/detect.md`.
