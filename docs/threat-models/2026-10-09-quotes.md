# Threat model: quotes

Branch `claude/pla-26-rzkr1l` (PLA-26, PLA-91, PLA-93). Required by the PR template because the change adds two tables with RLS and grants, the first ones every user reads, written by the `service_role` key.

## Scope and assets

The dollar rates (official, MEP, CCL, blue), the UVA and crypto prices that will value every user's holdings, and their integrity: a wrong row moves every user's net worth for that day. No user data is stored. The daily job (PLA-93) runs only under `next dev` for now, against the local database; registering it on a deployment is part of PLA-73.

## Trust boundary

Every authenticated user and `anon` on the PostgREST side. The `service_role` key, which bypasses RLS, on the server side. The providers' responses (dolarapi, argentinadatos, Kraken), which Plant does not control.

## Data flow

1. The daily job (`refresh-quotes` in `@plant/jobs`) fetches each feed and inserts what core kept through PostgREST with the `service_role` key, ignoring duplicates on the primary key. Each Inngest step reads and saves one feed and returns counts and keys only.
2. The guard trigger refuses any row not dated today in Buenos Aires.
3. Every signed-in user reads every row through PostgREST, behind the MFA gate.

## Where it is enforced

- Grants: `service_role` holds `INSERT` on every column and `SELECT` on the key columns; `authenticated` only `SELECT`; `anon` nothing. No API role holds `UPDATE`, `DELETE`, `TRUNCATE` or `TRIGGER`.
- RLS: `<table>_select_all` (`FOR SELECT TO authenticated USING (true)`) and the RESTRICTIVE MFA gate.
- Triggers: `fx_rates_guard` and `prices_guard` (`BEFORE INSERT`, `PT403`). They hold only while no role the API can become owns the tables, the guard functions, the `private` schema or a quote enum (whose owner can rename its values), can add a trigger, or may set `session_replication_role`; `quotes_test.sql` pins each of these and that both triggers are enabled.
- CHECKs: positive values that are not NaN, `buy <= sell`, no `buy` for UVA, symbols `^[A-Z0-9]{1,15}$`, `numeric(20, 8)` (which refuses `Infinity`).
- The pgTAP floor: no other public table without `user_id`, and none that lets `authenticated` write or read past a `SELECT USING (true)` policy.

## STRIDE

|       | Vector                                                                       | Control                                                                                                                                                                                                                       |
| ----- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S** | A user writes a quote as if it came from the job.                            | No write grant or policy for `authenticated` (pgTAP, pentest).                                                                                                                                                                |
| **T** | A user or a buggy job rewrites a past quote, or plants one for a future day. | No `UPDATE` or `DELETE` grant for any API role, directly or through a view that runs as its owner (floor); the guard refuses any date but today, before `ON CONFLICT` (pgTAP, pentest).                                       |
| **R** | Nobody can tell where a row came from.                                       | `source`, `quoted_at` and `fetched_at` on every row, with `source` and `fetched_at` stamped by the factory from the feed that read it; corrections go through migrations, which git records.                                  |
| **I** | Quotes leak.                                                                 | They are public market data; `anon` still reads nothing, and an enrolled user below `aal2` reads nothing.                                                                                                                     |
| **D** | Someone fills the tables.                                                    | Only the `service_role` key inserts, one row per kind or symbol and day; which symbols it writes is Kraken's fixed list in core.                                                                                              |
| **E** | A role turns the guard off or writes past the grants.                        | No role the API can become owns the tables, the guards, `private` or the quote enums, holds `TRIGGER` or may set `session_replication_role` (pinned in `quotes_test.sql`); no SECURITY DEFINER function touches these tables. |

## Controls as built

- **Tables**: `quotes_test.sql` covers the exact privileges of `service_role`, `authenticated` and `anon`, the bypass pin (no API role but `service_role` may insert; a canary per grant, table owner, `private` schema owner, guard function owner and enum owner clause, each in its own subtransaction; setting `session_replication_role` or holding the privileged role takes a superuser), the exact guard bodies and trigger definitions, that both guards date by Buenos Aires whatever the session time zone, the job's insert shape and its rerun, past and future dates (a future UVA included) and a past row that already exists, every refused verb, the owner's backfill and correction path, the MFA gate, and the exact columns, types, nullability and constraints, with no defaults and a CHECK case each. Replacing either guard with one that lets every row through or dates by the session, making it `AFTER INSERT`, disabling it, or granting `authenticated` `INSERT`, turns its asserts red.
- **Floor**: `schema_rls_and_grants_test.sql` limits reference tables to these two, their policies to `SELECT USING (true)` for `authenticated`, their write grants to `service_role`'s inserts, forbids them a foreign key, and bars inheritance and views that run as their owner and are writable by `service_role`, each with a canary.
- **PostgREST**: `fx-rates.pentest.test.ts` and `prices.pentest.test.ts` check that users read the same row and that POST, POST ignoring duplicates, PUT, PATCH and DELETE are refused, and that the service role's rerun returns nothing while a past row, an overwrite and a delete are refused; the anon sweep covers both tables.

## Provider data

The providers' responses are untrusted. `@plant/core` (PLA-91) checks them before anything can store them:

- Each adapter checks its response's shape with zod and throws `QuoteFeedError("bad_shape")` on a mismatch; a dolarapi house that fails is recorded as unread with its code, so the other houses are kept, and the read fails only when every house fails (with the code of a retryable failure if any, so four 4xx answers stay `http_4xx`). A read where every row is invalid is a `bad_shape`. A provider's own error (Kraken's `error` list, warnings aside) becomes `provider_busy`, retried, for a service, rate-limit, internal or temporary-lockout error, and `provider_error` otherwise. Every `QuoteFeedError` message is its code and its `retryable` comes from the code, so no provider text reaches a log line.
- The factory checks every row against schemas that mirror the tables' CHECKs: positive decimal strings within `numeric(20, 8)` (an exponent or a float artifact is an invalid row), `buy <= sell` compared exactly, no UVA buying rate, the symbol pattern, enum values, and instants stored in UTC within the years 1 to 9999 (Postgres refuses an offset beyond ±15:59 and the year 0). A test pins the symbol pattern to the migration's CHECK.
- Rows outside the window are refused, each under its key: kept when dated today in Buenos Aires, and for dollar rates and prices, read at or after `QUOTE_CLOSE_HOUR`; Friday's dollar rate on a weekend is `closed`, a traded row before the close `early`, any other date `stale`. The insert guard bounds the date again; the hour is bounded only here.
- The HTTP reader (`apps/web/src/lib/quotes/get-json.ts`) times out after 10 s, follows no redirect and refuses a body over 2 MB, by its length or while reading it; a bad body is `bad_json` with no part of it kept.
- The writer (`quote-writer.ts`) is the only service-role user for quotes, reached only through `quote-sink.ts`, which only the Inngest route imports (ESLint). It maps PostgREST's answer to a store code and keeps PostgREST's own code, never its message or details, which carry the row.

## Residual risk

- **The first writer of the day wins.** The guard bounds only the date; the hour and the value are whatever the first insert carried. A bad value stays until a migration corrects it.
- **The `service_role` key writes any value for today.** Anyone holding it already bypasses RLS everywhere; for quotes it has one writer.
- **In dev mode a caller controls memoized step output.** Steps return counts and keys only, so a forged answer can only put strings on the job's local log line; rows reach the database only from a feed's own read.
- **Which symbols get a price is not enforced.** Every user reads `prices`, so a symbol list derived from holdings (PLA-25) would show that some user holds a rare symbol. The database checks only the symbol's shape; the change that derives the list revisits the **I** row.
