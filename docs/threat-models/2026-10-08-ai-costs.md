# Threat model: AI costs

Branch `claude/pla-22-ai-costs-34rs9h` (PLA-22). Required by the PR template because the change adds a table with RLS and grants, and the first server-side code that holds the `service_role` key.

## Scope and assets

What each user's model calls cost (`ai_costs`: tokens and USD per call), the integrity of that record, which later drives quotas (PLA-42), and the `service_role` key, which bypasses RLS, signs in as any user through Auth's admin API and skips Storage policies. Out of scope: the model calls themselves and the prompts (PLA-36, PLA-47), the per-run seam into `packages/jobs` (PLA-36), retention (PLA-73).

## Trust boundary

The provider's usage counts in its response, which Plant does not control. The `userId` a caller puts in `AiCostContext`, which must come from the verified session or a row the server loaded. Untrusted text that a caller passes through `prompt-text.ts` before a prompt. On the PostgREST side, every authenticated user and `anon`.

## Data flow

1. A route handler (and, from PLA-36, an Inngest step through it) builds a model wrapped with `costMiddleware({ modelId, context, record: aiCostSink() })`.
2. The provider answers; the middleware reads its usage, prices it with `costUsd` by the requested model id and builds the row with `aiCostRow`.
3. The sink's writer inserts it through supabase-js with the `service_role` key, with a 1.5 s timeout.
4. The owner can read their own rows through PostgREST; nobody else can, and nobody can change them.

## Where it is enforced

- Grants: `service_role` holds only `INSERT` on the eight data columns; `authenticated` only `SELECT`; `anon` nothing.
- RLS: `ai_costs_select_own` (`user_id = (select auth.uid())`), and no policy for any other verb.
- ESLint over all of `apps/web`: only `service-role.ts` names `SUPABASE_SERVICE_ROLE_KEY` (or its `NEXT_PUBLIC_` form), only `ai-cost-sink.ts` imports it and only `src/app/api/**/route.ts` imports the sink, through static, `import()` or `require()` specifiers, with or without an extension; computed specifiers and `export … from` of either module are banned, and the sink and route handlers export only what they define; no `"use server"` in the sink or a route handler; `ai` and the provider packages only in `src/lib/ai`. A key name built at runtime passes the lint. `scripts/web-import-fences.test.mjs` lints each case.
- `check:boundaries`: `ai` and `@ai-sdk/*` declared only by `apps/web` and `evals`.
- `costMiddleware`: the only recorder and the only place a recording failure is swallowed.

## STRIDE

|       | Vector                                                                                                | Control                                                                                                                                                                                                                                                           |
| ----- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S** | A caller bills another user by passing their id; a server action exposes the sink to any client.      | `userId` only from `getSessionClaims().sub` or a server-loaded row (doc comment and decisions); the sink is fenced to route handlers and may not be a server action (ESLint).                                                                                     |
| **T** | A user inserts, edits or deletes cost rows to dodge a quota or inflate someone else's.                | No write grant or policy for `authenticated`; pgTAP checks each verb as the owner and, with grants added in a rolled-back block, that no policy lets them through; the pentest spec checks the same over PostgREST.                                               |
| **R** | A billed call leaves no row.                                                                          | `ai_cost.unbilled` for aborts, failed calls after the provider answered, streams without `finish`, stream errors and missing usage; `ai_cost.record_failed` when the insert fails (`unknown` on a timeout, fetch failure or 5xx, which may still have committed). |
| **I** | A user reads another user's costs; a log line or error carries the row.                               | Owner-only `SELECT` (pgTAP, pentest); the writer's errors are a closed set of codes, never `details` or `hint`; `ai_cost.*` lines carry ids, cost type and model, never tokens or amounts.                                                                        |
| **D** | A slow or down database makes every model call wait.                                                  | The writer gives up after 1.5 s, abort included, and the call succeeds anyway.                                                                                                                                                                                    |
| **E** | The `service_role` key leaks into client code or a second module, or the role reads or rewrites rows. | `server-only` on the client, writer and sink; one importer (ESLint); `service_role` cannot `SELECT`, `UPDATE`, `DELETE`, `TRUNCATE` or choose `id` or `created_at` (pgTAP).                                                                                       |

## Controls as built

- **Table**: `ai_costs_isolation_test.sql` (26 asserts) covers the service role's exact privileges, the owner's read, every write as the owner, `anon`, the policies past added grants, the amount, model id and token checks and the cascade; each of seven loosened grants or policies turns at least one of its asserts red.
- **PostgREST**: `ai-costs.pentest.test.ts` covers another user's reads and writes, the owner's writes and the `auth.users` embed.
- **Writer**: `ai-cost-writer.test.ts` runs the real supabase-js on a stubbed fetch: the amount as a string, each kind of error code and whether it may have committed, no row data in the error, the timeout with a fetch that ignores the abort, and no timer left behind.
- **Middleware**: `cost-middleware.test.ts` checks the exact row of a mock call, one row per step and per successful retry, every unbilled and record-failed path, and that a streamed step finishes after its row is recorded.

## Residual risk

- **The key's reach is wider than this table.** PLA-36 ships it to Vercel with its first caller and pins `service_role`'s privileges across the schema; until then no deployed code holds it.
- **Some calls can go unbilled.** An abort or a stream that never sends `finish` logs `ai_cost.unbilled`; a serverless function frozen or recycled while its row is in flight leaves no row and no line. The chat (PLA-47) must not pass the browser's abort signal to the model and keeps the request alive with `after()`. Until then quotas (PLA-42) must not rely on `ai_costs` alone.
- **Usage comes from the provider.** A provider that under-reports is billed as reported; a missing count writes no row and logs `ai_cost.unbilled` with `usage_missing`.
- **The owner sees what their own calls cost** through the API. The UI never shows dollars, and nothing about other users is exposed.
