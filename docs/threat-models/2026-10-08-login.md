# Threat model: login with an email code and Google

Branch `feat/pla-17-login-oj22lx` (PLA-17). Required by the PR template because the change adds authentication, a route handler, a redirect and a migration on `auth.users`.

## Scope and assets

The session (access and refresh tokens in cookies), the right to sign in as an address, and every page behind `(app)`. Out of scope: MFA (PLA-18, PLA-76), the CSP (PLA-19), audit rows and telemetry (PLA-21).

## Trust boundary

The email address, the code, `next`, the `error` query parameter, the callback's `code`, `error` and `error_code` parameters, the `plant-auth-next` cookie and every request header come from the browser. Google's identity comes through Supabase Auth, which verifies it.

## Data flow

1. `/login` (Server Component) reads Auth's settings to decide whether to show Google.
2. The browser calls Auth directly: `signInWithOtp`, then `verifyOtp`; or `signInWithOAuth`, which returns through Google to `/auth/callback` with a PKCE code.
3. `/auth/callback` exchanges the code with the verifier cookie and redirects to the sanitized `next` cookie.
4. On every page request `proxy.ts` verifies the access token (`getClaims`, local ES256 verify) and refreshes it when expired.
5. `(app)/layout.tsx` calls `getSessionClaims()` and renders the user from the `email` claim.

## Where it is enforced

- **Postgres:** the `clear_password` trigger on `auth.users`.
- **Supabase Auth config:** confirmations, code length and expiry, resend interval, exact redirect URLs, session limits.
- **`proxy.ts`:** refresh, the redirect to `/login`, stripping a client's `x-plant-auth`.
- **`/auth/callback`:** PKCE exchange, `sanitizeNextPath`, `no-store`.
- **`lib/auth/`:** `sanitizeNextPath`, `sanitizeAuthCode`, the closed error-copy map, `isSessionMissing`, `getSessionClaims`.

## STRIDE

|       | Vector                                                                                                                                                                                                         | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S** | Someone signs up with the victim's address and a password before the victim does, and keeps using the password after the victim confirms with a code. A stolen session sets a password that outlives sign-out. | No user can hold a password (`clear_password`); `auth.pentest.test.ts` and pgTAP. Passwords stored before the migration stay until the row changes: the staging checklist reviews existing users. Google and email identities link automatically only for verified emails; manual linking is off.                                                                                                                                                                                     |
| **T** | Open redirect through `next`; a planted `next` cookie; content spoofing through `?error=`; a forged `x-plant-auth`.                                                                                            | `sanitizeNextPath` everywhere; exact `additional_redirect_urls` plus PKCE; the cookie is scoped to `/auth/callback` and `vercel.app` is on the Public Suffix List, so a sibling host cannot set it; error copy comes from a closed map; `updateSession` strips `x-plant-auth`.                                                                                                                                                                                                        |
| **R** | Sign-ins and sign-outs leave no record in Plant.                                                                                                                                                               | Auth's own audit log. Plant's `audit_log` rows arrive with PLA-21.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **I** | A cached response carries someone's session cookie. A script on the page reads the refresh token.                                                                                                              | Supabase's no-cache headers are copied onto proxy responses and redirects; the callback sets `no-store`. The cookies are readable by JavaScript (`@supabase/ssr`) and there is no `script-src` until PLA-19 nor a session timebox on staging until PLA-73: an XSS means takeover until sign-out, with no password to make it last. Accepted only while the users are the team.                                                                                                        |
| **D** | Code guessing; mail flooding; one visitor exhausting a shared rate-limit bucket; Auth outages logging everyone out.                                                                                            | 6-digit code, 10 minutes, Auth's per-IP verify limit (the browser calls Auth, so the IP is the visitor's). The callback exchange and proxy refreshes share the server's IP until IP forwarding (before the beta). Mail: 60 s between sends per address and 2 per hour per project on the default sender; no captcha by decision. A rate limit or outage keeps the session and shows the retry page; in the browser auth-js still signs the user out on a non-retryable refresh error. |
| **E** | Trusting `user_metadata`; a deleted, banned or signed-out user keeps access.                                                                                                                                   | Only the verified `sub` and `email` claims are read. `getClaims` verifies locally, so an issued access token stays valid for up to 1 h after sign-out, deletion or a ban; the next refresh fails with a session-gone code and sends the user to `/login`.                                                                                                                                                                                                                             |

## Controls as built

- **No passwords:** `supabase/migrations/20261008090551_disable_password_login.sql`; `supabase/tests/auth_password_disabled_test.sql`; `security-tests/src/auth.pentest.test.ts` (both password cases fail without the migration).
- **Exact redirects and confirmations:** `supabase/config.toml`; `auth.pentest.test.ts`.
- **`next` sanitizer:** `safe-redirect.test.ts`, `routes.test.ts`, `auth/callback/route.test.ts`, `proxy.test.ts`.
- **Auth failure is not a logout:** `session-state.test.ts`, `proxy.test.ts`, `session-claims.test.ts`.
- **Error copy:** `login-errors.test.ts`.

## Residual risk

- **Hosted Auth is not tested continuously.** The specs run against the CLI's Auth; the staging checklist covers the dashboard settings.
- **XSS steals the session** until PLA-19 adds the CSP. Revisit before anyone outside the team signs in.
- **Shared server IP** for the callback exchange and refreshes, until IP forwarding (before the beta).
- **Up to 1 h of access** after sign-out, deletion or a ban.
